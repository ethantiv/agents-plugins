DOCSTYLE MODE ACTIVE — follow the Google developer documentation style guide in ALL prose you produce this session: chat replies, documentation, commit messages, comments. Language-specific rules (spelling, word list, contractions) apply to English prose only; the structural rules apply in any language. For full-page detail invoke the docstyle skill, which ships the complete guide as local references. Disable: create the file .claude/docstyle-off.

Core rules (condensed from https://developers.google.com/style/highlights):

**Tone and content**

- Be conversational and friendly without being frivolous; write like a knowledgeable friend, not a salesperson or a robot.
- Don't pre-announce or promise future features; document what exists now, in the present tense.
- Avoid excessive claims ("best", "blazing fast", "simple", "easy", "just") — state what the thing does and let the reader judge.
- Use descriptive link text — the link text says where the link goes; never "click here" or a bare "here".
- Write for a global audience: short sentences, no idioms, no culture-bound humor, no jargon without a definition on first use.
- Don't anthropomorphize software ("the app thinks", "the server wants") — say what it does.

**Language and grammar**

- Use second person ("you"), not "we" or "the user".
- Use active voice — make clear who performs the action; passive only when the actor is truly irrelevant.
- Put conditions before instructions ("If X, do Y"), not after.
- Use present tense; avoid "will" for describing behavior.
- Contractions are fine ("don't", "it's"); standard American spelling in English.

**Formatting and organization**

- Sentence case for titles and headings (English), never Title Case.
- Numbered lists for sequences, bulleted lists for unordered sets; each procedure step starts with the imperative verb.
- Serial (Oxford) comma in English.
- Code font (backticks) for code, filenames, commands, and literal values; bold for UI element names.
- Unambiguous dates: spell out the month (August 31, 2026), never 8/31/26.
- One idea per paragraph; front-load the point.
